Let your agents manage CapRover,read-only first.

better-caprover-mcp is an unofficial MCP server that lets any AI (such as Claude, Cursor, Codex, and others) deploy and manage apps on a self-hosted CapRover. It starts read-only: write tools aren't registered until you raise the mode, and deletes need a single-use token.

Write tools aren't registered. The model can't call what it never sees.

Guardrails in code,
not in the prompt.

A CapRover password is full access. Asking the model to be careful is a hope. Here the server enforces it before anything reaches CapRover.

Read-only by default

Write tools aren't registered until you start the server in another mode. The mode is an env var and changes only on restart, so the agent can't promote itself.

CAPROVER_MCP_MODE

Preview before you commit

Any change accepts a dry run. You get what would happen, and no write call goes to CapRover.

dry_run

Deleting needs a token

delete_app first returns a preview and a single-use token. It lasts 5 minutes and is tied to that exact call.

delete_app

Secrets stay out

Env var values are never returned, only whether they're set. The password is masked in logs and errors, and log lines show [REDACTED].

isSet · [REDACTED]

Deleting takes two calls and a yes.

The first delete_app call deletes nothing. The agent has to bring you the preview, get your answer, and call again with the token.

  • Single use. A spent token can't be replayed.
  • Five minutes. Then it expires.
  • Bound to the call. A token from another call is refused.

Four risk levels

the mode decides which exist

  • Read

    Registered in every mode. Never returns a password, token or environment variable value.

  • Write

    Registered from operate. Takes dry_run to preview the change first.

  • Destructive

    Registered in admin. Returns a preview and a single-use confirmation_token before anything is lost.

  • Critical

    Admin plus CAPROVER_MCP_ALLOW_CRITICAL=1: password, root domain, nginx, nodes, updates.

One command, then ask.

Start in readonly. Ask which apps run a latest tag. Raise the mode when you need writes.

{
  "mcpServers": {
    "caprover": {
      "command": "npx",
      "args": ["-y", "better-caprover-mcp"],
      "env": {
        "CAPROVER_URL": "https://captain.your-domain.com",
        "CAPROVER_PASSWORD": "your CapRover password",
        "CAPROVER_MCP_MODE": "readonly"
      }
    }
  }
}
docker run -d --name caprover-mcp -p 127.0.0.1:3100:3100 \
  -e CAPROVER_URL=https://captain.your-domain.com \
  -e CAPROVER_PASSWORD='your CapRover password' \
  -e CAPROVER_MCP_MODE=readonly \
  -e CAPROVER_MCP_TRANSPORT=http \
  -e CAPROVER_MCP_HTTP_HOST=0.0.0.0 \
  -e CAPROVER_MCP_HTTP_TOKEN='your-long-random-secret' \
  -e CAPROVER_MCP_LOG_LEVEL=info \
  -e CAPROVER_MCP_SURFACE=tools \
  ghcr.io/guilhermebkel/better-caprover-mcp:latest

Before you start

  • Your CapRover address, like captain.your-domain.com.
  • Its password. There is no username.
  • No two-factor auth on that server. It isn't supported yet.
  • Your own server: bind to localhost and put TLS in front for anything else.

Check the login first

init tests the login and prints the config for your client.

Every call takes the same road. Nothing skips a step.

  1. 01

    Mode

    Is this operation registered in the current mode?

  2. 02

    Schema

    Arguments are validated against the operation's schema.

  3. 03

    Preview

    A dry run, or a confirmation token for deletes.

  4. 04

    CapRover

    One adapter makes the API call.

  5. 05

    Redaction

    Secrets are masked before the answer leaves.

Private by construction

The only network traffic goes to your CAPROVER_URL. There is no telemetry.

The server doesn't run commands on your machine or read files. It only reads environment variables.

Built to be read

TypeScript on Node. One class per operation, each with its schema, risk level and description, and a single manifest feeds every interface and the policy.

The official caprover-api SDK is experimental, so only one adapter imports it. Integration tests run against a real, disposable CapRover.

Questions worth asking first.

Is this the official CapRover MCP?

No. It's unofficial and has no affiliation with CapRover.

Can the agent give itself more permissions?

No. The mode comes from an env var read when the server starts. Changing it means restarting the server, and the agent has no tool for that.

Why is there no “send any request” tool?

A raw request would walk around the mode, preview and redaction layers. The project records this decision as ADR 0003.

Does it work with two-factor auth?

Not yet. Servers with two-factor authentication aren't supported (ADR 0010).

Why does get_app_runtime fail on my server?

It needs a CapRover version that exposes that endpoint. CapRover 1.15.5 doesn't have it.

What's coming next?

The whole roadmap is done: #3 the rest of the CapRover API, #4 diagnose_app and find_issues, #5 a Code Mode with search and execute, and #6 remote HTTP (one CapRover server per MCP instance).
